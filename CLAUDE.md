# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Bilingual (ES/EN) marketing site for VanguardDevs — a boutique product studio founded by Jesus O., positioned on fintech / insurtech / lending: MVPs, multi-tenant SaaS and embedded infrastructure (widgets, SDKs, partner APIs) for clients in the USA, UK and LATAM. One page type: the one-page landing at `/[lang]` (plus `/[lang]/privacy`). Next.js App Router, TypeScript, plain global CSS (no Tailwind, no CSS modules). No test suite or linter is configured.

## Commands

```bash
npm run dev    # dev server at http://localhost:3000
npm run build  # production build; both locales prerender as static HTML (SSG)
npm run start  # serve the production build
```

`npm run build` is the main correctness check: it type-checks and prerenders `/es` and `/en`. To verify SEO output (hreflang, JSON-LD, redirects), run `next start` and curl the pages — see README "SEO checklist".

The only env var is `NEXT_PUBLIC_GA_ID` (`.env.example`). GA4 mounts only when all three hold: production build, value ≠ `PLACEHOLDER`, and the visitor accepted the `vg_consent` cookie — so dev never loads analytics and there is nothing to configure locally.

`graft/` is a gitignored, regenerable code graph (`graft build` after larger changes); `graft ask/grep/skeleton/callers` are the cheap way to locate code here before reading files. Also wired via `AGENTS.md` / `.cursor/rules/graft.mdc`.

## Architecture

Content and structure are fully decoupled:

- **`lib/dictionaries.ts`** is the single source of truth for ALL copy in both languages, as one typed `Dictionary` object per locale. Any content change happens here; components never contain literal copy. Changing the `Dictionary` interface requires updating both `es` and `en` objects (TypeScript enforces this).
- **`lib/i18n.ts`** defines `locales` (`es`, `en`), `defaultLocale` (`es`), and `siteUrl` (`https://vanguarddevs.com`).
- **`lib/site.ts`** holds external links and contact details: the VanguardDevs accounts (WhatsApp, company LinkedIn, email, Instagram), `JODAZ_URL` (the founder's own site, linked from the footer), and `BOOKING_URL`. `primaryCta(lang)` is the single source for where every primary CTA points — header, hero and contact all consume it, so filling in `BOOKING_URL` flips all three at once. Until then it returns WhatsApp everywhere. `PLACEHOLDER` is the repo-wide convention for a value the owner hasn't supplied; grep for it to see what's pending before launch.
- **`app/[lang]/`** is the root layout segment (there is intentionally no `app/layout.tsx` — the `[lang]` layout renders `<html lang>`). Both pages are SSG via `generateStaticParams` with `dynamicParams = false`. `generateMetadata` in the layout emits per-locale canonical/hreflang/OG tags; `page.tsx` composes the section components and inlines JSON-LD (`ProfessionalService` + `WebSite` + `WebPage`). The sibling route `privacy/` repeats the same `dynamicParams = false` + `generateStaticParams` + `generateMetadata` shape, so every route is SSG in both locales; `app/sitemap.ts` lists both.
- **404 handling** is a single file, `app/global-not-found.tsx` (Next's `experimental.globalNotFound`, enabled in `next.config.ts`). It renders the locale-agnostic `components/NotFound.tsx` (ES then EN copy together — a not-found page never receives route `params`) inside its own `<html lang="es">`/`<body>` — the **one exception** to "no root layout" — and is reached for every unmatched path (`/es/whatever`, `/xx`; bare `/whatever` is first redirected into `/[lang]` by `middleware.ts`). Why not a plain `app/not-found.tsx`: with no root `app/layout.tsx` (see below) Next 15 refuses it ("not-found.tsx doesn't have a root layout" — a 500 in dev), and adding a real root layout would cost either per-locale `<html lang>` on the actual pages or (via `headers()`) the static generation of `/es` and `/en` — both worse trades than a hard-coded `lang="es"` on a bilingual 404. Don't add `app/not-found.tsx` or `app/[lang]/not-found.tsx` alongside it.
- **`middleware.ts`** matches every path except Next internals, `api/` and anything with a file extension (which is what keeps `robots.txt`, `sitemap.xml`, `icon.svg`, `manifest.webmanifest` and `/public` assets out of it). It 307-redirects any unprefixed path to its locale version from `Accept-Language` — `/` → `/es`, `/privacy` → `/es/privacy` — with Spanish winning on ambiguity and when the header is empty; `/es/*` and `/en/*` pass through untouched. `/es` and `/en` are the canonical indexable URLs; never make `/` serve content.
- **`components/`** are almost all server components, with four documented exceptions: the vendored `components/reactbits/DotField` (canvas animation, used in the Hero and Contact sections) and `components/reactbits/BlurText` (word-reveal animation on section heads / hero / 404 — the only reason `motion` is a dependency; it respects `prefers-reduced-motion`), `components/ConsentBanner.tsx` (+ the small `components/CookieSettingsButton.tsx` it pairs with) — reading the `vg_consent` cookie server-side in `app/[lang]/layout.tsx` would force `/es`/`/en` off static generation, so consent gating and the conditionally-mounted GA snippet have to run client-side (both render nothing at all while `GA_ENABLED` is false, i.e. until a production build sees a real `NEXT_PUBLIC_GA_ID`). ConsentBanner also owns the one document-level click listener that turns any `data-track="name"` on an `<a>`/`<button>` into a GA4 `cta_click` event via `lib/analytics.ts` (`trackEvent`, a no-op until gtag is mounted) — that is how the server-rendered sections report clicks without becoming client components; and `components/ChatWidget.tsx` (landing-page chat: open state, streamed replies, focus). Don't add `"use client"` beyond these for anything achievable with CSS or links. Vendored ReactBits components (`components/reactbits/`) are fetched from their shadcn-style registry with curl (the jsrepo CLI doesn't work with it) and patched minimally with documented comments.
- **`app/globals.css`** holds the entire brand system keyed to CSS variables (`--paper`, `--ink`, `--signal`, `--signal-text`, `--on-signal`, `--steel`, `--tint`, `--rule`, `--rule-strong`, `--pad`) and font variables set by `next/font` in `lib/fonts.ts` (`--font-display` Anton, `--font-body` Archivo, `--font-mono` IBM Plex Mono), imported by `app/[lang]/layout.tsx` and `app/global-not-found.tsx`, the two `<html>`-rendering entry points, so they share one font config. The site is **light by default** (brand guide's primary scheme: `--paper` is Fog #ECEAF1 as surface, `--ink` is Obsidian #16121F as type/structure). Semantics, not colors: `--paper` = surface, `--ink` = type/structure, `--signal` = violet backgrounds, `--signal-text` = violet-as-text (#5D2DE2 on light), `--on-signal` = text over violet. Section components reuse shared class patterns (`.sec-head`, `.svc`, `.mono`, `.mark`, `.btn`, `.sec-cta`, `.case-quote`).

  Structure is carried by **hairlines, not black bars**: `--rule` is the 1px default divider and `--rule-strong` the few edges that must stay legible (section-head underline, the line closing a grid above a CTA). The sticky header is borderless, `--header-h` tall and an inverted `--ink` band like the hero (it is in the inverted-surface token list, so its hairlines and `--signal-text` are the light variants and hover/active states swap to `--paper` bg / `--ink` text): on the landing the hero runs under it (negative margin) and a CSS scroll-driven view timeline (`timeline-scope: --hero`, no JS) keeps the bar transparent over the hero (and the `.logo` hidden — it fades in with the bar), fading to opaque `--ink` as the hero's bottom edge passes the bar. Browsers without view timelines, reduced-motion, and pages without a `.hero` (privacy) simply get the opaque bar. The mobile `<details>` menu is dark too and animates open only (CSS keyframe; close can't animate without JS). Contrast comes from type scale and whitespace instead. Any change here has an accessibility floor: body text ≥ 4.5:1 against **both** `--paper` and the `--tint` hover/focus surface — that second case is why `--steel` is `#645E77` rather than the brand's raw Slate `#6F6A7C`, which fails. On the inverted `--ink` bands (`header`, `.hero`, `.cases`, `.contact`, `.not-found`) violet-as-text lifts to `#9B7BFF`; `.cases` additionally lightens `--steel`/`--tint` and shows a decorative ghosted screenshot (`CaseItem.image`, `public/cases/`) bleeding out of each card corner, since brand violet reaches only 2.6:1 on Obsidian; `--signal` as a *background* is never overridden, so accent scarcity holds.

  **Scrollbar** is branded once, in `globals.css`, identically for every engine and theme: `--scrollbar-thumb` (`#2D2540`, a violet-cast step up from Obsidian) on an Obsidian `--scrollbar-track` (`#16121F`), thin/rounded with no arrow buttons — Firefox via `scrollbar-color`/`scrollbar-width` on `:root`, Chromium via the `@supports selector(::-webkit-scrollbar)` block (which resets the standard properties, since Chromium ignores `::-webkit-*` pseudos while they're set). Change the colors by editing the two tokens only; a documented exception to "hairlines, not black bars".

  **There is no dark mode.** No page has a dark rendering; don't add theme toggles or `data-theme` scopes.
- **Chat widget** (`components/ChatWidget.tsx` + `components/chat-widget.css`, `app/api/chat/route.ts`, `lib/chat-prompt.ts`). Mounted only in `app/[lang]/page.tsx`, only when `GEMINI_API_KEY` is set (unset = no widget). The route streams `gemini-2.5-flash` via `@google/genai`; its system prompt is **derived** from `getDictionary(lang)` + `lib/site.ts` in `lib/chat-prompt.ts` — never hand-type a price, client or contact there. UI copy is `dict.chat`. `chat-widget.css` is the one stylesheet outside `globals.css` and deliberately uses its own `--chat-*` tokens and a system font stack, no brand tokens, so it can be lifted out. `robots.ts` disallows `/api/`.
- **Security headers** live in `next.config.ts` (`headers()`): HSTS (host only, no `includeSubDomains` while sibling subdomains are unverified), nosniff, `X-Frame-Options: DENY`, referrer and permissions policies, and a CSP shipped as `Content-Security-Policy-Report-Only`. Promote the CSP to enforcing only after production shows no violations; every allowed origin is commented next to it.
- **Page structure** (fixed by the owner): Hero → What we do / packages (`#services`, `components/Services.tsx`, `dict.services`) → Case studies (`#cases`) → Roadmap steps (`#process`, `components/Process.tsx`, `dict.process`) → Contact (`#contact`); the header nav follows the same order. Industries (`components/Industries.tsx`, `dict.industries`) is **hidden** by the owner (2026-09): the component, copy and CSS are kept but it is not mounted in `page.tsx` nor linked from the nav — re-add both to bring it back. The founder section (`components/Founder.tsx`) was removed (2026-09); `dict.about` survives only for the chat prompt and the Person JSON-LD. The founder profile page (`/[lang]/jodaz`) was removed; the footer links to the founder's own site (`JODAZ_URL`) under his real name (`footer.founderLink`). CTA is WhatsApp everywhere: the owner declined a booking link, so `BOOKING_URL` stays `PLACEHOLDER` and `primaryCta()` keeps returning WhatsApp (the branch is left in place should that change). No forms — the owner chose WhatsApp/email over a brief form (2026-09).
- **Section chrome**: package cards do **not** show prices (owner's call, 2026-09); `PackageItem.price` is kept only because the chat prompt quotes it. The Venezuela special-price note renders on `/es` only. The hero carries a mono trust line (`hero.trustLine`) that may only restate facts already in `about.bio`. `SectionHead` takes only a `heading` (no mono label); the numeric counters on cases/steps and the hero's region line are gone and their fields deleted — don't reintroduce a field without markup that renders it.
- **Planned, not built**: `docs/plans/notes-blog.md` specifies the `/[lang]/notes` section (MDX, SSG, RSS, Article JSON-LD). Build it only once the owner has the first note.
- `design-reference/` contains the original static HTML design — reference only, not served. `docs/plans/` holds design notes for shipped work (the analytics/consent plan there still says "not yet implemented" — the code is the source of truth).

## Project agents (`.claude/agents/`)

Delegate recurring work to these instead of doing it inline:

- **seo-auditor** — read-only SEO audit: metadata, hreflang, JSON-LD, sitemap, redirects, OG images.

## Copy rules (owner requirements — do not violate)

- The owner supplies copy verbatim; use it literally, never rewrite it. Mark missing content with `[PLACEHOLDER]`. **Never invent a price, metric, client name or date** — an unsupplied number ships as `$[PLACEHOLDER]`, not as a plausible guess. Case study `body` strings are plain-language descriptions of the problem and what the product does — the owner removed the technical explanations (2026-09); don't reintroduce implementation detail there.
- Voice is **fully impersonal**: no first person anywhere — neither "yo/I" nor "nosotros/we". VanguardDevs or the product is the subject. Second person addressing the visitor is fine.
- Use the founder's real name in display copy: **"Jesus O."**. The nickname "Jodaz" is never a *name* in visible copy, but the owner explicitly chose it for `JODAZ_URL` (`jodaz.vanguarddevs.com`, linked from the footer) — that's correct as-is.
- The hero must not contain "Fundado por…"/"Founded by…". The founder introduction lives only in `about.bio` / `about.photoLabel`, which feed the chat prompt — edit it in one place there.
- Spanish leads: `es` is the default and `x-default` locale. English is a first-class **rewrite for a US/UK buyer**, not a literal translation — calques of the Spanish clause order are a defect. Prices are USD in both locales; every package keeps a `desde`/`from` figure in the dictionary for the chat bot, though the cards don't display it. The Venezuela special-price block is local segmentation and renders on `/es` only.
- Brand accent (Voltage Violet `--signal`) is scarce by design — one highlighted element per surface.
